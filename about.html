sksurrogate/ about

Software you can audit, not just install.

SKSurrogate is an open-source, scikit-learn-native environment for optimizing expensive objectives — hyperparameter search, pipeline and experiment design — where every number it reports is traceable to a protocol, a seed and an archived record.

MIT licence Python 3 · scikit-learn v0.3.0 open development

What it is

SKSurrogate implements surrogate-guided optimization for objectives that are expensive to evaluate: each evaluation costs minutes rather than milliseconds, so the question is not how many candidates you can try but how much you learn from each one. The package builds a response surface over the space you have sampled, then uses that surface to decide where to spend the next evaluation.

Around that core it provides the machinery a research or production workflow actually needs: dataset registration with identity, a drop-in BaseSearchCV tuner, statistical evaluation with nested cross-validation and conformal intervals, sensitivity and dependence analysis, experiment design for expensive runs, a control plane that executes and logs searches, and a research workspace that keeps each claim attached to the evidence that supports it.

It is scikit-learn-native on purpose. Estimators, splitters, scorers and pipelines you already use keep working; SKSurrogate supplies the search layer and the evaluation discipline rather than a parallel ecosystem.

How it is developed

Development happens in the open on GitHub. The benchmark suite is part of the repository, not a marketing appendix: a frozen protocol contract, pre-registered hypotheses with explicit falsifiers, and raw run records archived with DOIs so a reader can check the advertised results without rerunning anything.

That has two consequences. The changelog is public and versioned; documentation lives at a stable address on Read the Docs instead of being regenerated per release; and when the data says the package does not beat a baseline, that is published too — see the honest benchmark post, which reports parity with Optuna-TPE at small budgets and a defect in our own pipeline that the study exposed.

Bug reports, feature requests and corrections go through the repository's issue tracker. Material corrections to published numbers are noted in the changelog rather than edited quietly.

Who maintains it

SKSurrogate is written and maintained by Mehdi Ghasemi, a scientist-mathematician working on optimization, statistics and scientific software. The project grows out of that work: the same insistence on pre-registration, reproducibility and honest reporting that applies to a paper applies to a software release here.

Contact is by email or through the issue tracker — see contact. There is no support contract and no service-level agreement attached to the project; it is maintained software, not a hosted product.
